# 雲端共用硬碟盤點 — 設計 spec

- 日期：2026-06-06
- 專案：`~/projects/drive-inventory`
- 階段：盤點建索引（整理的第一步，唯讀）

## 一句話

唯讀盤點 11 個 Google 共用硬碟，產出一份放進共用硬碟的 Google Sheet「全組織檔案地圖」（逐檔索引＋白話總覽），供道場團隊查用，並當作後續去重／重整的工作底稿。

## 目標

回答四個問題，並讓任何人都查得到：

1. **有什麼／放哪** — 每硬碟的檔數、類型分佈、資料夾樹
2. **多大** — 各硬碟佔用空間、最大的檔
3. **多舊** — 依最後修改時間分桶，標出長年沒動的沉睡區
4. **哪些重複** — 用 MD5 內容雜湊找出完全相同的檔（跨硬碟也抓）

## 非目標（YAGNI，這階段不做）

- 不搬移、改名、刪除任何既有檔案
- 不改動任何資料夾結構
- 不自動執行去重（只標示候選，刪不刪由人決定）
- 不做個別檔案的語意分類／重新歸檔
- 不碰未編碼 4 個硬碟的重整（之後階段）

## 架構與資料流

```
授權 → 爬取 → 路徑重建 → 落地 → 分析 → 輸出 Sheet
```

1. **授權**：Google Drive API（read-only scope）。規劃時先驗證既有 Google Workspace / gdrive 憑證能否直接用，不行則帶 Neil 做一次性 OAuth。
2. **爬取**：Python 腳本遞迴每個 driveId（`supportsAllDrives=true`、`includeItemsFromAllDrives=true`、`corpora=drive`），分頁抓完。每檔抓欄位：`id, name, mimeType, size, md5Checksum, createdTime, modifiedTime, viewedByMeTime, owners, parents, driveId, trashed, shortcutDetails`。
3. **路徑重建**：用 `parents` 在本機組出每檔的完整路徑（硬碟名 / 資料夾 / … / 檔名）。
4. **落地**：寫 `data/inventory.csv`（＋ `data/raw.jsonl` 原始備份，供重算不重爬）。
5. **分析**：用 pandas 算總覽、年齡分桶、MD5 重複群組、最大檔排行。
6. **輸出**：用 Sheets API 在共用硬碟內建立／更新 Google Sheet，分多個分頁。

## 輸出規格（Google Sheet 分頁）

全部用**中文欄名**（不用英文 enum），首列凍結、開啟篩選。

- **索引** — 全部檔案逐列：硬碟 · 完整路徑 · 檔名 · 類型 · 大小 · 建立日 · 修改日 · 最後開啟日 · 擁有者 · 連結
- **各硬碟總覽** — 每硬碟：檔數 / 總大小 / 類型分佈 / 最舊 / 最新
- **重複清單** — MD5 相同且筆數 >1 的群組，含「可省空間」估算與每筆連結
- **最大檔 Top 100** — 佔空間大戶
- **沉睡區** — 最後修改 >5 年未動
- **說明** — 產製時間、口徑定義、資料來源

**Sheet 放置**：預設建在 A. 共用資源 硬碟（最偏「工具/管理」性質），Neil 可移到任何位置。

## 錯誤處理

- **API 配額／429**：指數退避重試
- **大量分頁**：每硬碟存進度檔，中斷可續爬
- **無權限子項**：記錄並跳過，不中斷整體
- **Google 原生檔**（Docs/Sheets/Slides 無 size/md5）：大小記 NA；不參與 MD5 去重，改在重複清單以「同名候選」另列供人工判斷
- **shortcut／多重 parent**：標記，路徑取第一個 parent 並註記歧義

## 邊界與風險

- **唯一的寫入動作**＝建立那份 Google Sheet（Neil 已選擇此輸出形式並授權）。其餘全程唯讀，不碰任何既有檔案。
- 憑證限定 read-only scope，降低誤動風險。
- 這是共用硬碟、多人在用：本階段刻意不動結構，正是因為動結構會打斷別人的書籤與找檔習慣。

## 驗收

- 11 個硬碟全部爬完，且 Sheet「索引」列數 = 腳本回報的檔案總數
- 「各硬碟總覽」檔數加總 = 索引總列數（內部一致）
- 「重複清單」任抽一組，點兩個連結確認 MD5 確實相同
- 重跑冪等：同一份 `raw.jsonl` 重算，產出的數字一致
- 大小／日期等數字有實際抽樣核對，不是「應該對」

## 後續階段（不在本 spec）

1. 去重執行（依重複清單，人工確認後刪）
2. 未編碼 4 個硬碟（8~11）的重整與命名規則
3. 長期維運：定期重跑、新檔命名規範、權限收斂
